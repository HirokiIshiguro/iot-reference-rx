# RX の割り込み優先度一覧

iot-reference-rx の現行構成を記録する。FreeRTOS の ceiling は 4。UART CLI は SCI の受信コールバックから FreeRTOS のキューへ文字を渡す。現行の優先度、処理経路、適用条件を以下の基準と個別表に記載する。

RX72N の LCD 有効構成では、r_simple_graphic の描画 CMT と連続 UART 受信が重なると受信が遅れる可能性がある。評価は「RX72N の画面描画と連続受信」に示す。

## 対象と判定

- iot-reference-rx の main `14c7a9c6f9d544c387fafafe1da7806d44720abc` の `Projects` はアプリ6件とブートローダ3件。!286 の TSIP 互換アプリ1件は参考構成。
- EK-RX671 と RX72N Envision Kit のベンチマークは各リポジトリの main を対象とする。合計12件のうち3件はファームウェアを持たない。参照コミットは個別表に記載する。
- 「合う」は選択した構成のソースが基準表の経路と値に一致することを示す。「合わない」は基準行から外れる構成差を示す。構成差の解消や遅延要件の達成は別に判断する。
- 割り込みの受理直後、RX は PSW.I をクリアする。IPL が高い割り込みも、先行 ISR が再許可しなければその復帰まで待つ。実機・リンクマップによる確認状況は個別表と末尾に記載する。[RXv3 ソフトウェアマニュアル](https://www.renesas.com/en/document/mas/rx-family-rxv3-instruction-set-architecture-users-manual-software-rev100)

設計の判断には、ceiling を超える ISR からの FreeRTOS API 呼び出し禁止、遅延の許容範囲、グループの IPR 共有を確認する。[FreeRTOS 割り込み優先度の設計ルール](https://gitlab.saffti.jp/oss/claude-codex-gemini-index/-/blob/0038442ae3f66cad3331900079bd250069ba70f7/docs/development/decision-notes.md#L149)

## RX72N の画面描画と連続受信

### openai-live の観測

2026-11-27 に共有された実機観測では、`R_SIMPLE_GRAPHIC_Open()` が `R_CMT_CreatePeriodic()` で CMT1 を 60 Hz、IPL 4 で使用していた。コールバックは 80×34 セル、2,720 byte を `memcmp` で比較し、差分があれば描き直す。多重割り込みの再許可は無効。ISR 時間は未測定で、数十 µs は見積もりである。CMT1 停止版は3回とも取りこぼし0。稼働版は約6,000文字で毎回1〜3文字を落とした。この結果は openai-live の構成に対応する。

共有された IER・IPR の読み出しは、`SWINT2`（26）1、`SWINT`（27）1、`CMT0`（28）1、`CMT1`（29）4、SCI7 RXI（98）15、TXI（99）1、GROUPBL0（110）15 で有効な要因なし、GROUPAL0（112）15 で SCI7 ERI、GROUPAL1（113）4 で Ether EINT と GLCDC VPOS。SCI7 RXI 15 は openai-live の試験設定である。［根拠］依頼時に共有された観測記録。CMT の呼び出し、コールバック、ベクタは L・C・V。

### プロジェクトごとの遅延許容

921600 bps・8N1 で約10.85 µs/文字。ハードウェアの保持容量を超える前に RXI が受信レジスタを読み出す必要がある。表示は通常、次周期への遅延を許容できる。UART は長文の連続受信時には遅延を許容しにくい。FreeRTOS アプリでは IPL 1 と 3 のどちらの受信経路も ceiling 4 のクリティカルセクションでマスクされる。ソースでは、iot-reference-rx の SCI7 を IPL 1 で開いた後、CLI の受信キュー初期化で IPL 3 を書く。実機でどちらになっているかは対象版の IPR を読む必要がある。[SCI7 Open](https://gitlab.saffti.jp/oss/import/github/renesas/iot-reference-rx/-/blob/14c7a9c6f9d544c387fafafe1da7806d44720abc/Demos/cli/serial.c#L146)・[CLI の Control](https://gitlab.saffti.jp/oss/import/github/renesas/iot-reference-rx/-/blob/14c7a9c6f9d544c387fafafe1da7806d44720abc/Demos/cli/serial.c#L270)

| RX72N の構成 | r_simple_graphic と SCI RXI | 遅延を許すか・評価 |
|---|---|---|
| 親 `aws_ether_rx72n_envision_kit`、`aws_ether_rx72n_envision_kit_tsip`、!286 互換構成 | LCD 有効時に描画 CMT 4。CMT0 が tick なので描画は CMT1 と見込む。SCI7 は Open 1、CLI 初期化後 3 | 描画側は許容。SCI は連続貼り付けで許容しにくい。同種の描画との競合とクリティカルセクションによる遅延があり得る。取りこぼしと時間は未測定 |
| `mbedtls`、`tsip_mbedtls`、`tsip_mbedtls13` | LCD 有効時の描画 CMT は 4。SCI7 は共通 CLI。描画チャネルは空き順から CMT1 と見込む | 親と同じ条件で競合があり得る。欠落の発生と上限は未測定 |
| `mbedtls-primitive`、`tsip`、`tsip_tls`、`tsip_tls13` | 先行2チャネルを LED と計測が使用した場合、描画は CMT2、IPL 5。SCI7 RXI は 15 | 連続受信では実行中の描画 ISR の終了待ちがあり得る。FreeRTOS のマスクは適用されない。欠落は未測定 |
| 親 `boot_loader_rx72n_envision_kit` | GLCDC VPOS は 5。起動経路に r_simple_graphic の周期起動は見当たらず、計測 CMT も無効。SCI7 RXI は 15 | 描画 CMT との組み合わせは該当なし。Flash などとの連続受信条件は個別表を参照 |
| `readme`、`tsip_compat_mbedtls` | main にファームウェアなし | 該当なし |

### 対処を検討する場合の選択肢

| 選択肢 | 確認する点 |
|---|---|
| 描画を止める、または連続入力中だけ保留する | 画面表示の用途と更新停止時間。openai-live には CMT 停止時の比較結果がある |
| 描画 CMT の優先度を変える | 同時に保留中の割り込みの順序が変わる。先に走り始めた描画 ISR が RXI を待たせる時間は残る |
| 描画 ISR の処理を短くする | 差分比較と描き直しをタスクへ移す、または1回の描画量を制限する案。通常・最大差分時の ISR 時間、表示の追従、連続受信時の ORER を比較する |
| 連続入力を分割する | 送信側が制御できる用途で、文字間隔やブロック間の同期が表示と受信を両立できるか確認する |

## 表の読み方

- RX の IPL は数字が大きい方が上です。4 以下は FreeRTOS のクリティカルセクションでマスクされます。OS レス構成の上下は数値比較です。
- `未測定` は ISR の入口から復帰までの長さです。処理量の記述はソースに基づく見積もりです。最悪実行時間や µs の測定値は、対象と測定区間が一致する記録を確認できた場合にだけ記載します。
- 個別ベクタは RXI・TXI が別 IPR、グループは同じ IPR です。初期値に加え Open/Control が反映する値を記載します。IRQ 要因の登録、マスク解除、実際の発火は段階が異なります。
