# RX72N Transport run-copy preparation

This dedicated API-only branch prepares and checks a private IDT run copy. It never starts IDT, FRQ, AWS, a UART, RFP or a board. Its root CI is for this isolated experiment and must not replace the product's normal CI. The existing sample ref remains separate.

`tools/idt/rpi4_transport_overlay.py` accepts an official Linux ZIP, an owned private parent directory, and absolute paths to the extracted pinned QEMU executable and x86-64 sysroot. It checks QEMU and the loader/libraries by SHA-256, copies the ZIP into a new private directory, verifies its pinned archive hash and the original immutable tree, then changes only `tests/FRQ_2.5.0/suite/transportInterfaceTLS/tls/test.json` in that private copy. The original Linux `cmd` and two Transport arguments must match exactly. The new command is the fixed QEMU path, with `-L`, the fixed sysroot, the unmodified FRQ executable path, then those original arguments. The original ZIP and executable bytes are not modified. A private provenance JSON records the archive, QEMU, FRQ, and original/modified test-definition hashes; the caller owns and must remove the returned run directory after its processes stop.

The modified run copy intentionally fails the original manifest check for `test.json`; it is not an unmodified vendor suite and cannot be presented as qualification evidence. The isolated CI check compares every originally immutable file with the pinned manifest, requires exactly this one test-definition difference, checks provenance and verifies the source ZIP is unchanged. It downloads the same pinned Ubuntu packages as the sample CI, verifies package and extracted executable/library hashes, and removes its temporary directory.

This is not a complete Transport launcher. Remaining design and verification include the vendor's treatment of the modified definition, x86-64 subprocesses other than the explicitly selected FRQ, the existing Windows CC-RX build callback and private inputs/outputs, RPi #1 UART/flash ownership, report verification and cleanup, and AWS identity/permissions/spend and independent cleanup. Actual Transport is outside this experiment. A human must review the final architecture, scoped permissions and hardware execution before any new live run; no runner, IAM or host-binfmt change is made here.
